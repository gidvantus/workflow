# Макет · несколько окон времени работы (issue #50)

Статичный прототип на токенах `app/frontend/src/index.css`: новых цветов, гарнитур, теней, радиусов и
зависимостей нет. Открывается двойным щелчком, без сборки. Скриншоты — `mockups-50-1440.png` и
`mockups-50-375.png` в каталоге артефактов проекта, в репозиторий не едут.

## Кадры

1. **Список отделов** на странице проекта, вкладка «Отделы»: 4 отдела — одно окно, два, три; у первого
   окна «Разработки» переход через полночь. У последней строки раскрыто «⋯».
2. **Новый отдел, одно окно** — то, что человек видит чаще всего; кнопки удаления нет, потому что
   единственное окно удалить нельзя.
3. **Изменить отдел, три окна** — окна подставлены с сервера в серверном порядке, у каждого ряда крестик.
4. **Шесть окон** — предел: «Добавить окно» неактивна, подсказка на месте, окна идут встык
   (`00:00–04:00 … 20:00–00:00`), последнее переходит через полночь.
5. **Отправка и отказ** — «Сохраняю…» (кнопки и крестик неактивны, окно не закрывается) и отказ
   `Окна времени работы пересекаются` дословно, поля времени с `aria-invalid`.
6. **Состояния карточки списка** — «Загрузка…», «Пока нет отделов» с подсказкой, «Сервер не отвечает» +
   «Повторить». Форма от этого не меняется, показана ради полноты раздела.

## Что решено и почему

- **Колонка времени 9.5 rem вместо 8.5 rem, без новых полей.** Внутри ячейки окна стоят друг под другом,
  а не строкой через запятую: разряды `13:00` и `07:00` встают друг под другом, и набор читается как
  расписание. Запятая остаётся концом предыдущей строки — строка никогда не начинается со знака
  препинания. `white-space: nowrap` снят только у значения (перенос — между окнами), внутри окна
  `13:00–04:00` не рвётся.
- **Одно окно выглядит ровно как раньше**: та же одна строка значения и та же строка длительности.
  Самый частый случай задача не должна утяжелять.
- **Сумма и «через полночь» — одна служебная строка под окнами** (`17 ч · через полночь`, `9 ч`).
  Пометки у отдельного окна нет: `end < start` видно в самом значении, а второй маркер дублировал бы
  смысл и потребовал нового элемента. `department-item-time` содержит только окна.
- **В форме подпись «Время работы» одна на весь список.** Прежние подписи «с» и «по» у каждого ряда
  дали бы двенадцать подписей на шесть окон; порядок «начало — тире — конец» и подсказка снимают вопрос.
  Для скринридера у каждого поля своя подпись `.sr-only`: «Окно 1: начало», «Окно 1: конец».
- **Кнопка удаления — тот же `.kebab`** (1.75 rem, прозрачная рамка, подсветка на наведении), что в
  строке списка: новых размеров и токенов нет. `aria-label="Удалить окно N"`, нумерация с 1.
  Видимых номеров «Окно 1…6» нет: номер уже в подписи кнопки, а колонка цифр в форме — шум.
- **«Добавить окно» — обычная `.btn` слева под списком**, подсказка — под ней. При одном окне кнопки
  удаления нет (вместо неактивной), при шести неактивна «Добавить окно» (`opacity: .45` из продукта).
- **Отказ — только серверный текст**: `.error` под формой, `aria-describedby` на окне; своих проверок
  пересечения на фронте нет, поэтому в кадре 5.2 окна `13:00–04:00` и `03:00–05:00` уже введены и
  сохранение остаётся доступным.

## Тексты

- Форма: «Время работы» (подпись списка), «Добавить окно», «Сохранить» / «Сохраняю…», «Отмена».
- Подсказка дословно: «Если конец раньше начала, окно идёт через полночь. Окон может быть до шести.»
- Отказы, которые видит человек (с сервера, без правок на фронте): «Укажите хотя бы одно окно времени
  работы», «Окон времени работы не может быть больше шести», «Окна времени работы пересекаются»;
  прежние — «Время работы указывается как ЧЧ:ММ, например 09:00», «Начало и конец рабочего времени
  совпадают», «Отдел с таким названием уже есть», «Нет полей для изменения».
- Список: окна как `13:00–04:00, 07:00–09:00` (короткое тире внутри окна, запятая между окнами),
  длительность «9 ч», «17 ч · через полночь», «11 ч · через полночь»; счётчик «4 отдела».

## Брейкпоинты

- **1440** — как в макете: пять колонок, время 9.5 rem, окна в столбик.
- **≤900** — меню полосой, шапка колонок скрыта, строка в стопку: название, время, роли, дата, «⋯».
  Окна остаются в столбик — в широкой колонке это читается лучше строки через запятую.
- **≤600** — одна колонка, «Добавить отдел» в шапке карточки, роли в один столбец, диалог на всю ширину.
- **375** — ряд окна остаётся одним: `10:00 — 14:00 ×`. Пробовал переносить крестик на вторую строку —
  в ряду появляется пустая полоса, а поле времени всё равно сжимается; остановился на одном ряду,
  поля получают ~7 rem, этого хватает для «ЧЧ:ММ». Отдельного медиазапроса под это нет.

## Чего в макете нет

- Поведения: обработчиков, добавления и удаления ряда, ловушки фокуса, Esc, запросов. Состояния
  показаны блоками.
- Пустого состояния «окон ноль» (`Укажите хотя бы одно окно времени работы`): через форму оно
  недостижимо — последнее окно удалить нельзя, кнопки удаления у него нет. Текст всё равно остаётся в
  контракте для `windows: []`/`null` через API.
- Состояния «роли грузятся / роли не загрузились» и `409` — они не меняются этой задачей; в кадрах
  показаны только те состояния, которые трогают окна.
- Подтверждения удаления, экрана «Все отделы», календаря, дней недели, именованных графиков,
  перетаскивания окон, тёмной темы, новых иконок и анимаций.
- Порядка окон на фронте: макет показывает серверный порядок (по возрастанию начала), сортировки и
  переформатирования времени на клиенте нет.
