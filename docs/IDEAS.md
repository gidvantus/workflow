## 1. Мульти-агентная структура проекта (ролевые пресеты)

**Идея:** разбить работу над проектом на ролевых агентов, как в команде разработки.

**Пресеты агентов:**
| Пресет | Роль | Инструменты | Отвечает за |
|---|---|---|---|
| `dev` | Разработчик | fs, pwsh, read/write | Написание и правка кода |
| `tester` | Тестировщик | fs, pwsh, bash | Написание и запуск тестов, отчёты |
| `devops` | Деплой-инженер | pwsh, сеть | Сборка, деплой на тестовую среду |

**Как реализуется в DSH:**
- Пресеты = отдельные файлы в `~/.dsh/.agent-presets/<id>/` (копия `cordis`-пресета + свои промпт/инструменты);
- Сессии создаются с нужным пресетом через `agents.create({ meta: { agentPreset } })`;
- В Telegram-боте — команда `/new <preset>` для создания сессии конкретной роли.

**Ценность:** изоляция прав (тестировщик не трогает прод, девопс не пишет код), понятная ответственность, параллельная работа.

## 2. Workflow-конвейер «код → тесты → деплой»

**Идея:** один запуск из бота прогоняет полный цикл.

**Схема (workflow-скрипт):**
```
Фаза 1: dev     — задача → код в ветке/папке
Фаза 2: tester  — запуск тестов → отчёт
Фаза 3: решение — тесты зелёные? → devops : вернуть в dev на исправление
Фаза 4: devops  — сборка + деплой на тестовую среду
```

**Как реализуется в DSH:**
- Скрипт workflow (инструмент `workflow`) оркеструет фазы через `agent()`-вызовы;
- Между фазами передаётся структурированный результат (JSON: статус, артефакты, ошибки);
- В Telegram-боте — команда `/pipeline <задача>`, запускающая конвейер для активной сессии.

**Ценность:** конвейер повторяем, одна команда = полный цикл, результаты видны в боте.

## 3. Постоянная «команда» агентов (Agent Teams)

**Идея:** вместо разовых запусков — долгоживущая команда агентов, которые общаются между собой.

**Как реализуется в DSH:**
- Сервис `agentTeams`: `spawnTeammate`, `sendMessage`, `createTask`, статусы участников;
- Роли (`dev`/`tester`/`devops`) живут как участники одной команды, ставят задачи друг другу;
- В боте — обзор команды: кто что делает, какие задачи открыты.

**Ценность:** ближе к реальной командной работе; агенты сами координируют исправления без ручного запуска.

## 4. Несколько ботов по ролям (альтернатива №1)

**Идея:** отдельный Telegram-бот на каждую роль (свой токен + свой пресет).

- Бот-разработчик, бот-тестировщик, бот-деплой — каждый привязан к своей роли;
- Минус: координация между ботами вручную; **предпочтителен вариант №1–3** (агенты внутри DSH уже умеют общаться).

---

## 5. Стабильное мобильное подключение (Telegram-мост)

**Идея:** убрать зависимость от нестабильного канала ПК → api.telegram.org.

**Варианты:**
- 💭 **Укрепление моста** (без нового железа):
  - одно постоянное HTTPS-соединение (keep-alive) вместо node.exe на каждый запрос;
  - авто-резолв: при обрыве пробовать несколько официальных IP Telegram и обновлять hosts;
  - умные ретраи с экспоненциальной паузой.
- 🚧 **VPS + Tailscale** (рекомендуется):
  - мост живёт на VPS (стабильный интернет), опрашивает Telegram 24/7;
  - VPS ⇄ ПК через Tailscale (mesh-VPN, без публичного IP);
  - бот работает, даже когда ПК перезагружается (мост на VPS пережидает).
- 💭 **Tailscale serve для GUI** — полный веб-интерфейс DSH с телефона в приватном тайлнете.

## Приоритет (моё предложение)

1. 🚧 **VPS + Tailscale** — стабильность прежде всего;
2. 💭 **Ролевые пресеты** (`dev`/`tester`/`devops`) — база для всего остального;
3. 💭 **Workflow-конвейер «код → тесты → деплой»** — первая польза от ролей;
4. 💭 **Agent Teams** — когда роли станут «жить» постоянно;
5. 💭 UX-доработки бота (по мере необходимости).
